Bun's security toolkit covers password hashing, fast non-cryptographic hashing, incremental cryptographic hashing/HMAC, CSRF tokens, and OS-native secret storage — all first-party, no npm packages.

Bun.password — hashing passwords

Argon2id by default (or bcrypt). The algorithm and salt are embedded in the hash, so verify figures everything out.

const hash = await Bun.password.hash("super-secure-pa$$word");
// $argon2id$v=19$m=65536,t=2,p=1$...salt...$...hash...

const ok = await Bun.password.verify("super-secure-pa$$word", hash);  // true

// choose the algorithm / cost
const argon = await Bun.password.hash(pw, {
  algorithm: "argon2id", memoryCost: 65536, timeCost: 2,
});
const bcrypt = await Bun.password.hash(pw, { algorithm: "bcrypt", cost: 12 });

// sync variants exist but block — avoid in request handlers
Bun.password.hashSync(pw);
Never store or log the plaintext. Bun.password.hash generates a random salt automatically; with bcrypt, passwords over 72 bytes are pre-hashed with SHA-512 instead of being silently truncated.

Bun.hash — fast non-cryptographic hashing

For hash tables, checksums, sharding — not for security. Wyhash by default.

Bun.hash("some data");            // 64-bit bigint
Bun.hash("some data", 1234);      // with a seed

Bun.hash.crc32("data");
Bun.hash.xxHash64("data");
Bun.hash.cityHash64("data");
Bun.hash.murmur32v3("data");

Bun.CryptoHasher — cryptographic hashing & HMAC

const hasher = new Bun.CryptoHasher("sha256");
hasher.update("hello ");
hasher.update("world");
hasher.digest("hex");             // "b94d27b9934d3e08..."
// digest() also accepts "base64" / "base64url", or a TypedArray to fill

// HMAC — pass a key to the constructor
const mac = new Bun.CryptoHasher("sha256", "secret-key");
mac.update("hello world");
mac.digest("hex");

Supported algorithms include sha1, sha256, sha384, sha512, the sha3-* family, blake2b*, md5, shake128/256, and more.

The HMAC hasher does not reset after digest() — create a new instance per message, or copy() before digesting.

Bun.CSRF — CSRF tokens

Signed, HMAC-based tokens with an issue timestamp and expiry. Always pass a sessionId to bind a token to one user.

const token = Bun.CSRF.generate("my-secret", {
  sessionId: "user-session-id",
  expiresIn: 60 * 60 * 1000,       // 1 hour (ms)
});

const valid = Bun.CSRF.verify(token, {
  secret: "my-secret",
  sessionId: "user-session-id",
});                                 // boolean

A typical form flow with Bun.serve: issue a per-session token when rendering the form, embed it in a hidden field, verify it on POST.

const SECRET = Bun.env.CSRF_SECRET!;

Bun.serve({
  routes: {
    "/form": (req) => {
      const sessionId = getSession(req);            // from your session cookie
      const token = Bun.CSRF.generate(SECRET, { sessionId });
      return new Response(
        `<form method="POST" action="/submit">
           <input type="hidden" name="_csrf" value="${token}">
           <button>Send</button>
         </form>`,
        { headers: { "Content-Type": "text/html" } },
      );
    },
    "/submit": {
      POST: async (req) => {
        const sessionId = getSession(req);
        const form = await req.formData();
        const token = form.get("_csrf");
        if (typeof token !== "string" ||
            !Bun.CSRF.verify(token, { secret: SECRET, sessionId })) {
          return new Response("Invalid CSRF token", { status: 403 });
        }
        return new Response("OK");
      },
    },
  },
});

Bun.secrets — OS credential storage

Store credentials in the OS keychain (macOS Keychain / Linux libsecret / Windows Credential Manager) instead of plaintext dotfiles. Ideal for CLI tools and local dev.

import { secrets } from "bun";

let token = await secrets.get({ service: "my-cli", name: "github-token" });

if (!token) {
  token = prompt("GitHub token?")!;
  await secrets.set({ service: "my-cli", name: "github-token", value: token });
}

await secrets.delete({ service: "my-cli", name: "github-token" });
Confirmed against the Bun 1.4.2 reference: get, set, and delete each take { service, name } (set also takes value, and an optional allowUnrestrictedAccess). It's designed for local development tools — use real secret management (or env vars) for production servers.

Real-life example: signup, login & API keys

An auth module a route layer would call — password hashing on signup, verification on login, and issuing hashed API keys (store only the hash; show the raw key once).

import { timingSafeEqual } from "node:crypto";

// Signup — hash the password (argon2id), never store plaintext
export async function signup(email: string, password: string) {
  if (password.length < 10) throw new Error("weak password");
  const passwordHash = await Bun.password.hash(password);   // argon2id + random salt
  return db.insert(users).values({ email, passwordHash }).returning();
}

// Login — verify is constant-time and self-describing (reads the algorithm from the hash)
export async function login(email: string, password: string) {
  const user = await findUserByEmail(email);
  // Always run a verify even when the user is missing, to avoid leaking
  // account existence through response timing.
  const hash = user?.passwordHash ?? "$argon2id$v=19$m=65536,t=2,p=1$AAAA$AAAA";
  const ok = await Bun.password.verify(password, hash);
  if (!user || !ok) throw new Error("invalid credentials");
  return user;
}

// Issue an API key: return the raw key ONCE, persist only its SHA-256
export async function issueApiKey(userId: number) {
  const raw = "sk_" + crypto.randomUUID().replaceAll("-", "");
  const keyHash = new Bun.CryptoHasher("sha256").update(raw).digest("hex");
  await db.insert(apiKeys).values({ userId, keyHash });
  return raw;                     // show once — it is never recoverable again
}

// Verify an incoming API key in constant time
export async function verifyApiKey(raw: string) {
  const keyHash = new Bun.CryptoHasher("sha256").update(raw).digest("hex");
  const row = await findApiKeyByHash(keyHash);
  if (!row) return null;
  // timingSafeEqual guards against timing attacks on the hash comparison
  const a = Buffer.from(keyHash), b = Buffer.from(row.keyHash);
  return a.length === b.length && timingSafeEqual(a, b) ? row.userId : null;
}
Why hash the API key: if your DB leaks, raw keys would be usable immediately — SHA-256 of a high-entropy random key means the leak is inert. (Passwords need a slow KDF like argon2 because they're low-entropy; random API keys don't, so a fast hash is fine.) Combine with the JWT refresh-token flow for browser sessions and Bun.CSRF for cookie-authenticated form posts.
