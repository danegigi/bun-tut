Bun's package manager is a drop-in replacement for npm/yarn/pnpm — it reads package.json, installs from the npm registry, and is dramatically faster thanks to a global cache and a binary lockfile.

Install, add, remove

bun install                 # install everything in package.json
bun add hono                # add a dependency
bun add -d @types/bun       # dev dependency
bun add zod@3.23.8          # pin an exact version
bun add -g wrangler         # global tool
bun remove hono             # remove
bun update                  # update within semver ranges
Prefer exact/pinned versions for reproducibility. Bun writes a binary bun.lockb lockfile — commit it, and never hand-generate package-lock.json or yarn.lock alongside it.

The lockfile

bun.lockb is binary (fast to parse). To read it as text in a diff or review:

bun install --frozen-lockfile   # CI: fail if lockfile would change
bun pm ls                       # list the installed tree
bunx --bun ...                  # force tools to run under Bun, not Node

bun outdated

bun outdated
# Package   Current  Update  Latest
# hono      4.6.1    4.6.3   4.6.3
# zod       3.23.8   3.23.8  3.24.1

Workspaces (monorepos)

// package.json (repo root)
{
  "name": "my-monorepo",
  "private": true,
  "workspaces": ["packages/*", "apps/*"],
  "engines": { "bun": ">=1.0.0" }
}

Then a package can depend on a sibling by name and Bun symlinks it:

// apps/web/package.json
{ "dependencies": { "@myorg/ui": "workspace:*" } }
bun install                       # links all workspaces
bun run --filter='*' build        # run "build" in every workspace

bunx — run a package without installing

bunx cowsay "hello from bun"     # like npx, but fast
bunx --bun vite                  # ensure it runs on Bun's runtime

Scripts

Define scripts with bun, and run them with bun run <name>:

// package.json
{
  "scripts": {
    "start": "bun run src/index.ts",
    "dev": "bun --watch src/index.ts",
    "test": "bun test",
    "build": "bun build src/index.ts --outdir dist"
  },
  "engines": { "bun": ">=1.0.0" }
}
bun run dev
bun start        # "start" and "test" can skip the "run" keyword

Real-life example: a reproducible CI install

The install step of a CI pipeline for a workspace monorepo — deterministic, dev-deps included for building/testing, cached between runs.

# .github/workflows/ci.yml (excerpt)
- uses: oven-sh/setup-bun@v2
  with:
    bun-version: 1.4.2

# Fail if the lockfile would change — catches an un-committed dependency bump
- run: bun install --frozen-lockfile

# Build + test every workspace in one pass
- run: bun run --filter='*' build
- run: bun test

And the matching root package.json for a monorepo with a shared UI package consumed by two apps:

{
  "name": "acme",
  "private": true,
  "workspaces": ["packages/*", "apps/*"],
  "engines": { "bun": ">=1.0.0" },
  "scripts": {
    "build": "bun run --filter='*' build",
    "typecheck": "bunx tsc --noEmit"
  }
}
Real-world workflow: run bun install locally (updates bun.lockb), commit the lockfile, and let CI run --frozen-lockfile so a drifted lockfile fails the build instead of silently resolving different versions. Use overrides in the root package.json to pin a transitive dependency across every workspace at once.
