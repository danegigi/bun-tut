This section covers everything you need to build command-line tools with Bun: the Bun.$ shell, terminal utilities, subprocess spawning, and the built-in Bun.cron scheduler — ending with a small CLI app that ties them together.

Bun.$ — the shell

Bun.$ is a cross-platform shell as a tagged template. It works the same on macOS, Linux, and Windows (no bash needed), and interpolated values are escaped automatically.

import { $ } from "bun";

// Run a command, inherit stdout
await $`echo Hello from the shell`;

// Capture output
const branch = (await $`git rev-parse --abbrev-ref HEAD`.text()).trim();

// Parse JSON output
const pkg = await $`cat package.json`.json();

// Interpolation is escaped — safe against injection
const dir = "my files";
await $`ls ${dir}`;          // ls 'my files'

// Pipes and redirection
await $`cat access.log | grep ERROR > errors.txt`;

// Don't throw on non-zero exit
const { exitCode, stderr } = await $`false`.nothrow();

Terminal utilities

// stdin / stdout streams
const line = await Bun.stdin.text();

// Colorize for the terminal (ANSI). Bun.color converts many inputs -> ANSI
const green = Bun.color("#22c55e", "ansi");
console.log(`${green}success\x1b[0m`);

// Correct display width (handles emoji + CJK wide chars)
Bun.stringWidth("hi");      // 2
Bun.stringWidth("🥟");      // 2  (wide)
Bun.stringWidth("日本");     // 4
Bun.stringWidth is what you want for aligning columns in a terminal table — "🥟".length is 2 code units but the glyph occupies 2 columns, and CJK characters occupy 2 columns each. String.length gets both wrong.

Bun.Terminal — pseudo-terminals (PTY)

Bun.Terminal creates a real PTY so you can drive interactive terminal programs (a shell, vim, an SSH session) and capture their output — the backbone of a web terminal or a test harness for CLI apps.

await using terminal = new Bun.Terminal({
  cols: 80,
  rows: 24,
  data(term, data) {
    process.stdout.write(new TextDecoder().decode(data));   // stream PTY output
  },
});

// Spawn a shell attached to the PTY
const proc = Bun.spawn(["bash"], { terminal });

terminal.write("echo hello\n");      // send input
terminal.resize(120, 40);            // handle a window resize
terminal.setRawMode(true);           // pass input through unprocessed

await proc.exited;                   // terminal auto-closes via `await using`
The data(term, bytes) callback receives raw PTY output (including ANSI escape sequences) as it arrives. write() buffers anything that can't flush immediately, so never re-send based on its return value. termios flags (controlFlags, inputFlags, localFlags, outputFlags) are exposed for advanced control.

Bun.spawn — subprocesses

// Async spawn
const proc = Bun.spawn(["echo", "hello"], { stdout: "pipe" });
const out = await new Response(proc.stdout).text();
await proc.exited;            // wait for exit
console.log(proc.exitCode, out);

// Synchronous spawn
const { stdout, exitCode } = Bun.spawnSync(["git", "status", "--short"]);
console.log(exitCode, stdout.toString());

// Feed stdin
const cat = Bun.spawn(["cat"], { stdin: "pipe", stdout: "pipe" });
cat.stdin.write("piped input\n");
cat.stdin.end();
console.log(await new Response(cat.stdout).text());

Bun.cron — scheduling

Bun.cron is a first-class scheduler. It has three shapes: an in-process job (runs a callback on a schedule inside your process), an OS-level job (survives restarts via crontab/launchd/Task Scheduler), and a parser.

In-process jobs

// Runs every 5 minutes inside this process
const job = Bun.cron("*/5 * * * *", async () => {
  await syncToDatabase();
});

// The handle is Disposable — `using` auto-stops it at scope exit
using hourly = Bun.cron("0 * * * *", () => console.log("tick"));

job.cron;      // "*/5 * * * *"
job.stop();    // cancel — never fires again
job.unref();   // let the process exit even while scheduled

Two guarantees worth knowing: Bun computes the next fire only after your handler's promise settles, so invocations never overlap; and a time zone can be pinned with { tz }.

// Fire at 09:00 New York time regardless of server TZ
Bun.cron("0 9 * * *", handler, { tz: "America/New_York" });

Parsing schedules

const next = Bun.cron.parse("30 9 * * MON-FRI");   // next weekday 09:30, local
Bun.cron.parse("@daily");                          // next midnight
Bun.cron.parse("0 9 * * *", Date.now(), { tz: "UTC" });  // 09:00 UTC

// null when no occurrence within 8 years (e.g. Feb 30)
Bun.cron.parse("0 0 30 2 *");   // null

Nicknames: @yearly, @monthly, @weekly, @daily/@midnight, @hourly.

OS-level jobs

These run a script module on a schedule and survive restarts. The script exports a scheduled() handler (the Cloudflare Workers Cron Triggers shape).

// register (Linux crontab / macOS launchd / Windows Task Scheduler)
await Bun.cron("./worker.ts", "30 2 * * MON", "weekly-report");
await Bun.cron.remove("weekly-report");   // uninstall by title
// worker.ts
export default {
  scheduled(controller: Bun.CronController) {
    console.log(controller.cron, controller.scheduledTime);
  },
};
In-process vs OS-level: in-process is lightweight, shares state (DB pools, caches), and needs no daemon — but does not survive process exit. OS-level survives reboots but runs a fresh process each time. On Windows, Task Scheduler caps a task at 48 triggers, so step patterns that don't divide 60 (like */7 * * * *) can be rejected — restrict the hour range or use a divisor of 60.

Worked example: a small CLI

A todo CLI that stores items in a JSON file, using argv, Bun.file/Bun.write, colored output, and Bun.stringWidth for alignment.

#!/usr/bin/env bun
// todo.ts  —  usage: ./todo.ts add "buy milk" | list | done 2
const FILE = Bun.file("todos.json");
type Todo = { text: string; done: boolean };

const todos: Todo[] = (await FILE.exists()) ? await FILE.json() : [];
const save = () => Bun.write(FILE, JSON.stringify(todos, null, 2));

const c = (hex: string, s: string) => `${Bun.color(hex, "ansi")}${s}\x1b[0m`;
const [, , cmd, ...rest] = Bun.argv;

switch (cmd) {
  case "add":
    todos.push({ text: rest.join(" "), done: false });
    await save();
    console.log(c("#22c55e", "added:"), rest.join(" "));
    break;

  case "done": {
    const i = Number(rest[0]);
    if (todos[i]) { todos[i].done = true; await save(); }
    console.log(c("#22c55e", `done #${i}`));
    break;
  }

  case "list":
  default:
    todos.forEach((t, i) => {
      const box = t.done ? c("#22c55e", "[x]") : "[ ]";
      // pad the index to width 3 using display width
      const idx = String(i).padStart(3);
      console.log(`${idx} ${box} ${t.text}`);
    });
}
chmod +x todo.ts
./todo.ts add "write the bun tutorial"
./todo.ts add "🥟 ship it"
./todo.ts list
./todo.ts done 0
