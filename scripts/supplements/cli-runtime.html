The bun CLI is the entry point to the runtime. It runs files and scripts, watches for changes, and hot-reloads a running server.

Running code

bun run index.ts        # run a file
bun index.ts            # "run" is optional for files
bun run dev             # run a package.json script
bun --print "1 + 1"     # evaluate and print an expression -> 2
bun -e 'console.log(Bun.version)'   # evaluate a snippet

Watch vs hot reload

--watch restarts the whole process on file change. --hot reloads modules in place, keeping state and open sockets (ideal for servers).

bun --watch script.ts      # restart on change (CLIs, scripts)
bun --hot server.ts        # hot-reload modules, keep the server up
Under --hot, long-lived resources like Bun.serve() and in-process Bun.cron() jobs are re-registered cleanly on each reload — no leaked timers or dropped connections.

Shebang scripts

Make a TypeScript file directly executable:

#!/usr/bin/env bun
// tool.ts
console.log("args:", Bun.argv.slice(2));
chmod +x tool.ts
./tool.ts a b c        # args: [ "a", "b", "c" ]

Useful flags

FlagWhat it does
--watchRestart process on file change
--hotHot-reload modules, preserve state
--print / -eEvaluate an expression / snippet
--filterRun a script across matching workspaces
--env-file=.env.prodLoad a specific env file
--smolReduce memory use (smaller heap)
--sql-preconnectOpen a PostgreSQL connection at startup

Reading input

// Read all of stdin
const input = await Bun.stdin.text();
console.log("got", input.length, "chars");

// Arguments
const [, , cmd, ...rest] = Bun.argv;   // skip bun + script
console.log({ cmd, rest });
