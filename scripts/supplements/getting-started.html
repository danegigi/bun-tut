Bun is an all-in-one JavaScript & TypeScript runtime, package manager, bundler, and test runner. It runs .ts and .tsx files directly — no compile step — and ships a large native standard library under the global Bun namespace. This tutorial targets Bun 1.4.2.

Install

# macOS / Linux
curl -fsSL https://bun.com/install | bash

# Homebrew
brew install oven-sh/bun/bun

# Windows (PowerShell)
powershell -c "irm bun.com/install.ps1 | iex"

# Check it
bun --version   # 1.4.2

Create a project

bun init            # interactive scaffold: package.json, index.ts, tsconfig, .gitignore
bun init -y         # accept all defaults

A fresh index.ts runs with:

bun run index.ts
# or just
bun index.ts

Run TypeScript natively

Bun executes TypeScript and JSX with no tsc, ts-node, or tsx shim. Type checking is separate — Bun strips types to run fast; use bunx tsc --noEmit when you want type errors.

// hello.ts
const name: string = "world";
console.log(`Hello, ${name}!`);
bun hello.ts        # Hello, world!

bunfig.toml

Project (or global ~/.bunfig.toml) config. A minimal example:

# bunfig.toml
[install]
# use an alternate registry
registry = "https://registry.npmjs.org"

[test]
# preload a setup file before tests
preload = ["./test/setup.ts"]

[run]
# silence the "$ bun run ..." echo
silent = true

Environment variables

Bun auto-loads .env, .env.local, .env.<NODE_ENV> without dotenv. Read them via Bun.env (or process.env).

# .env
API_URL=https://api.example.com
PORT=3000
console.log(Bun.env.API_URL);        // https://api.example.com
console.log(process.env.PORT);       // 3000  (same values)
Precedence: real environment variables override .env.local, which overrides .env. Never commit secrets — keep them in .env.local (gitignored) and reference by name.

A first real program

// greet.ts
const who = Bun.argv[2] ?? "world";      // Bun.argv[0]=bun, [1]=script
console.log(`Hello, ${who}!`);
console.log(`Running on Bun ${Bun.version} (${Bun.revision.slice(0, 7)})`);
bun greet.ts Ada
# Hello, Ada!
# Running on Bun 1.4.2 (…)
