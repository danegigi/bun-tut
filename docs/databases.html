Bun has two built-in database APIs: bun:sqlite, a fast low-level SQLite driver, and Bun.sql (via Bun.SQL), a unified Promise-based client for PostgreSQL, MySQL, and SQLite using tagged-template queries.

bun:sqlite — the low-level SQLite driver

import { Database } from "bun:sqlite";

const db = new Database("app.db");           // or ":memory:"
db.run("CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)");

// Prepared statements (reused, fast)
const insert = db.query("INSERT INTO users (name) VALUES (?)");
insert.run("Alice");
insert.run("Bob");

// Query rows
const all = db.query("SELECT * FROM users").all();       // [{id,name}, ...]
const one = db.query("SELECT * FROM users WHERE id = ?").get(1);
const names = db.query("SELECT name FROM users").values(); // [["Alice"], ...]

// Named parameters
db.query("SELECT * FROM users WHERE name = $name").all({ $name: "Alice" });

Transactions

const insertMany = db.transaction((people) => {
  for (const name of people) insert.run(name);
});
insertMany(["Carol", "Dave", "Eve"]);   // all-or-nothing
Enable WAL mode for better concurrency: db.run("PRAGMA journal_mode = WAL"). Use bun:sqlite when you want direct, synchronous SQLite access; use Bun.sql below when you want one API across databases.

Bun.sql — unified SQL client

The same tagged-template interface targets Postgres (default), MySQL, or SQLite, chosen from the connection string. Values in ${...} are always parameterized — safe against SQL injection.

import { sql, SQL } from "bun";

// PostgreSQL (default) — uses DATABASE_URL / POSTGRES_URL env vars
const users = await sql`SELECT * FROM users WHERE active = ${true} LIMIT ${10}`;

// MySQL
const mysql = new SQL("mysql://user:pass@localhost:3306/mydb");
await mysql`SELECT * FROM users WHERE id = ${42}`;

// SQLite
const lite = new SQL("sqlite://app.db");
await lite`SELECT * FROM users WHERE id = ${1}`;

Inserting & the sql() helper

const user = { name: "Alice", email: "alice@example.com" };

// object helper expands to (name, email) VALUES (...)
const [created] = await sql`INSERT INTO users ${sql(user)} RETURNING *`;

// bulk insert from an array of objects
const many = [{ name: "Bob" }, { name: "Carol" }];
await sql`INSERT INTO users ${sql(many)}`;

// pick columns
await sql`INSERT INTO users ${sql(user, "name")}`;   // name only

Result formats

await sql`SELECT * FROM users`;          // [{ name, email }, ...]  (default: objects)
await sql`SELECT * FROM users`.values(); // [["Alice","a@x"], ...]  (arrays)
await sql`SELECT * FROM users`.raw();    // [[Buffer, Buffer], ...] (binary)

Dynamic fragments (safely)

const minAge = 21;
const ageFilter = sql`AND age > ${minAge}`;
await sql`
  SELECT * FROM users
  WHERE active = ${true}
  ${wantAge ? ageFilter : sql``}
`;

// dynamic table name (escaped)
await sql`SELECT * FROM ${sql("users")}`;

// WHERE IN
await sql`SELECT * FROM users WHERE id IN ${sql([1, 2, 3])}`;

Transactions & savepoints

await sql.begin(async (tx) => {
  await tx`INSERT INTO users (name) VALUES (${"Alice"})`;
  await tx`UPDATE accounts SET balance = balance - 100 WHERE user_id = 1`;
  // auto-COMMIT on success, auto-ROLLBACK on throw

  await tx.savepoint(async (sp) => {
    await sp`UPDATE users SET status = 'active'`;
    // can roll back to here independently
  });
});

Connection pooling & reserved connections

const pool = new SQL({ max: 20, idleTimeout: 30 });

// exclusive connection from the pool
using reserved = await pool.reserve();
await reserved`SELECT 1`;         // auto-released at scope end

await pool.close();               // drain and close

LISTEN / NOTIFY (PostgreSQL)

const sub = await sql.listen("orders", (payload) => {
  console.log("new order", JSON.parse(payload));
});
await sql.notify("orders", JSON.stringify({ id: 42 }));
await sub.unlisten();

Typed errors

try {
  await sql`INSERT INTO users (id) VALUES (1)`;
} catch (err) {
  if (err instanceof SQL.PostgresError) console.log(err.code, err.detail);
  else if (err instanceof SQL.SQLiteError) console.log(err.code, err.errno);
}
Large integers: Postgres bigint and out-of-range MySQL BIGINT come back as strings by default to avoid precision loss. Pass { bigint: true } to the client to get real BigInt values instead.

Drizzle ORM on Bun

Drizzle is a typesafe SQL query builder + migration toolkit. It layers a fully-typed schema and query API over a driver — here bun:sqlite — while staying close to SQL (no heavy runtime, no N+1 surprises). Install:

bun add drizzle-orm
bun add -d drizzle-kit @types/bun

Schema

// src/db/schema.ts
import { sqliteTable, int, text, index } from "drizzle-orm/sqlite-core";

export const users = sqliteTable("users", {
  id: int().primaryKey({ autoIncrement: true }),
  name: text().notNull(),
  email: text().notNull().unique(),
  createdAt: int("created_at", { mode: "timestamp" }).notNull().$defaultFn(() => new Date()),
});

export const posts = sqliteTable("posts", {
  id: int().primaryKey({ autoIncrement: true }),
  authorId: int("author_id").notNull().references(() => users.id),
  title: text().notNull(),
  published: int({ mode: "boolean" }).notNull().default(false),
}, (t) => [ index("posts_author_idx").on(t.authorId) ]);

Connect & query

// src/db/index.ts
import { drizzle } from "drizzle-orm/bun-sqlite";
import { eq, and, desc, sql as dsql } from "drizzle-orm";
import { users, posts } from "./schema";

export const db = drizzle(Bun.env.DB_FILE_NAME ?? "app.db");

// Insert (typed — $inferInsert derives the input type)
const [alice] = await db.insert(users)
  .values({ name: "Alice", email: "alice@example.com" })
  .returning();

// Select with filters
const active = await db.select().from(users).where(eq(users.email, "alice@example.com"));

// Update / delete
await db.update(users).set({ name: "Alice B." }).where(eq(users.id, alice.id));
await db.delete(posts).where(eq(posts.published, false));

Migrations with drizzle-kit

// drizzle.config.ts
import { defineConfig } from "drizzle-kit";
export default defineConfig({
  out: "./drizzle",
  schema: "./src/db/schema.ts",
  dialect: "sqlite",
  dbCredentials: { url: Bun.env.DB_FILE_NAME ?? "app.db" },
});
bunx drizzle-kit push        # fast: apply schema directly (dev)
bunx drizzle-kit generate    # emit versioned SQL migration files
bunx drizzle-kit migrate     # apply generated migrations (prod)

Advanced: joins, relations, transactions

// Join posts to their authors, newest first
const feed = await db
  .select({ title: posts.title, author: users.name, at: posts.id })
  .from(posts)
  .innerJoin(users, eq(posts.authorId, users.id))
  .where(eq(posts.published, true))
  .orderBy(desc(posts.id))
  .limit(20);

// Aggregation with the magic `sql` operator
const counts = await db
  .select({ authorId: posts.authorId, n: dsql<number>`count(*)` })
  .from(posts)
  .groupBy(posts.authorId);

// Transaction — rolls back on throw
await db.transaction(async (tx) => {
  const [u] = await tx.insert(users).values({ name: "Bob", email: "bob@x.com" }).returning();
  await tx.insert(posts).values({ authorId: u.id, title: "Hello", published: true });
});

Drizzle also drives Postgres (drizzle-orm/bun-sql or node-postgres) and MySQL — the schema builder and query API are the same; only the column-type imports and driver change.

Real-world tip: keep drizzle-kit push for local iteration, but commit generated SQL migrations and run migrate in CI/production so schema changes are reviewable and reproducible. Pair Drizzle with drizzle-zod to derive request validators from the same schema.

MongoDB on Bun

MongoDB works on Bun with no special configuration — both the official mongodb driver and Mongoose run as-is.

Native driver

bun add mongodb
import { MongoClient } from "mongodb";

const client = new MongoClient(Bun.env.MONGO_URL ?? "mongodb://127.0.0.1:27017");
await client.connect();
const db = client.db("shop");
const orders = db.collection("orders");

// Insert
const { insertedId } = await orders.insertOne({ userId: 1, total: 99, status: "pending", at: new Date() });

// Query with an index-friendly filter + projection
const pending = await orders
  .find({ status: "pending" }, { projection: { total: 1, userId: 1 } })
  .sort({ at: -1 })
  .limit(50)
  .toArray();

// Update
await orders.updateOne({ _id: insertedId }, { $set: { status: "paid" } });

// Aggregation pipeline — revenue per user
const revenue = await orders.aggregate([
  { $match: { status: "paid" } },
  { $group: { _id: "$userId", total: { $sum: "$total" } } },
  { $sort: { total: -1 } },
]).toArray();

await client.close();

Transactions

const session = client.startSession();
try {
  await session.withTransaction(async () => {
    await orders.insertOne({ userId: 1, total: 50, status: "paid" }, { session });
    await db.collection("accounts").updateOne(
      { userId: 1 }, { $inc: { balance: -50 } }, { session },
    );
  });
} finally {
  await session.endSession();
}
MongoDB multi-document transactions require a replica set (even a single-node one). For local dev: start mongod with --replSet rs0 and run rs.initiate() once.

Mongoose (schemas & models)

bun add mongoose
import mongoose, { Schema, model } from "mongoose";

await mongoose.connect(Bun.env.MONGO_URL ?? "mongodb://127.0.0.1:27017/shop");

const orderSchema = new Schema({
  userId: { type: Number, required: true, index: true },
  total: { type: Number, required: true, min: 0 },
  status: { type: String, enum: ["pending", "paid", "refunded"], default: "pending" },
}, { timestamps: true });

const Order = model("Order", orderSchema);

const order = await Order.create({ userId: 1, total: 99 });
const paid = await Order.find({ status: "paid" }).sort("-createdAt").lean();
await Order.updateOne({ _id: order._id }, { status: "paid" });

Real-life example: an order API layer

A small repository module that a Hono route (see Web Dev) would call — showing where each tool fits: Bun.sql for ad-hoc analytics, Drizzle for typed app queries.

// orders.repo.ts
import { db } from "./db";
import { sql } from "bun";
import { orders } from "./db/schema";
import { eq, desc } from "drizzle-orm";

export const OrdersRepo = {
  // Typed app query via Drizzle
  listForUser: (userId: number) =>
    db.select().from(orders).where(eq(orders.userId, userId)).orderBy(desc(orders.id)),

  create: (userId: number, total: number) =>
    db.insert(orders).values({ userId, total, status: "pending" }).returning(),

  // Ad-hoc reporting via Bun.sql (raw, parameterized) against the same Postgres
  dailyRevenue: () => sql`
    SELECT date_trunc('day', created_at) AS day, sum(total) AS revenue
    FROM orders WHERE status = ${"paid"}
    GROUP BY 1 ORDER BY 1 DESC LIMIT 30
  `,
};
Choosing between them: reach for bun:sqlite/Bun.sql when you want raw control or a zero-dependency footprint; reach for Drizzle when you want end-to-end type safety and migrations across a growing schema; reach for MongoDB when your data is document-shaped and schema-flexible. They coexist — many services use Drizzle for the core relational model and MongoDB for event logs or flexible metadata.
