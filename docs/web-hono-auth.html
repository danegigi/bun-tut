🔑 Web Dev: Hono + Auth + Storage

This section builds a small web app on Bun: routing and middleware with Hono, a JWT auth flow with refresh tokens stored in HttpOnly cookies, an SSO (OAuth2/OIDC) login, and object storage with the built-in Bun.s3.

Hono is a third-party framework (not a Bun builtin) but pairs perfectly with Bun's Bun.serve. Install a pinned version: bun add hono@4.6.3.

A basic Hono app on Bun

// server.ts
import { Hono } from "hono";

const app = new Hono();

app.get("/", (c) => c.text("Hello from Hono on Bun"));
app.get("/users/:id", (c) => c.json({ id: c.req.param("id") }));
app.post("/echo", async (c) => c.json(await c.req.json()));

// middleware
app.use("*", async (c, next) => {
  const t = Bun.nanoseconds();
  await next();
  c.header("X-Response-Time", `${(Bun.nanoseconds() - t) / 1e6}ms`);
});

export default app;      // Bun auto-serves a default export with a fetch handler
bun --hot server.ts      # http://localhost:3000

JWT with refresh tokens in HttpOnly cookies

The pattern: a short-lived access token (~15 min) the client sends on each request, and a long-lived refresh token (~7 days) stored in an HttpOnly; Secure; SameSite cookie that JavaScript can't read — mitigating XSS token theft. /refresh rotates the pair.

import { Hono } from "hono";
import { sign, verify } from "hono/jwt";
import { setCookie, getCookie, deleteCookie } from "hono/cookie";

const app = new Hono();
const ACCESS_SECRET = Bun.env.ACCESS_SECRET!;
const REFRESH_SECRET = Bun.env.REFRESH_SECRET!;

const now = () => Math.floor(Date.now() / 1000);
const accessToken  = (sub: string) => sign({ sub, exp: now() + 60 * 15 }, ACCESS_SECRET);
const refreshToken = (sub: string) => sign({ sub, exp: now() + 60 * 60 * 24 * 7 }, REFRESH_SECRET);

function setRefreshCookie(c: any, token: string) {
  setCookie(c, "refresh_token", token, {
    httpOnly: true,
    secure: true,             // HTTPS only
    sameSite: "Strict",
    path: "/refresh",         // cookie only sent to the refresh route
    maxAge: 60 * 60 * 24 * 7,
  });
}

// LOGIN — verify credentials, issue both tokens
app.post("/login", async (c) => {
  const { email, password } = await c.req.json();
  const user = await findUser(email);
  if (!user || !(await Bun.password.verify(password, user.passwordHash))) {
    return c.json({ error: "invalid credentials" }, 401);
  }
  setRefreshCookie(c, await refreshToken(user.id));
  return c.json({ accessToken: await accessToken(user.id) });
});

// REFRESH — rotate: verify the cookie, issue a fresh pair
app.post("/refresh", async (c) => {
  const token = getCookie(c, "refresh_token");
  if (!token) return c.json({ error: "no refresh token" }, 401);
  try {
    const payload = await verify(token, REFRESH_SECRET);
    setRefreshCookie(c, await refreshToken(payload.sub as string));   // rotate
    return c.json({ accessToken: await accessToken(payload.sub as string) });
  } catch {
    return c.json({ error: "invalid refresh token" }, 401);
  }
});

// LOGOUT — clear the cookie
app.post("/logout", (c) => {
  deleteCookie(c, "refresh_token", { path: "/refresh" });
  return c.json({ ok: true });
});

// PROTECTED — validate the access token from the Authorization header
app.get("/me", async (c) => {
  const auth = c.req.header("Authorization") ?? "";
  const token = auth.replace(/^Bearer /, "");
  try {
    const payload = await verify(token, ACCESS_SECRET);
    return c.json({ userId: payload.sub });
  } catch {
    return c.json({ error: "unauthorized" }, 401);
  }
});

Store password hashes with Bun.password (see Security & Crypto), and add a CSRF token to state-changing form posts if you also accept cookie-authenticated requests.

SSO (OAuth2 / OIDC)

Redirect the user to a provider (Google/GitHub), receive an authorization code on your callback, exchange it for the provider's token, fetch the profile, then issue your own session tokens (reusing the flow above).

const GITHUB_CLIENT_ID = Bun.env.GITHUB_CLIENT_ID!;
const GITHUB_CLIENT_SECRET = Bun.env.GITHUB_CLIENT_SECRET!;
const REDIRECT_URI = "http://localhost:3000/auth/callback";

// 1) Send the user to the provider
app.get("/auth/github", (c) => {
  const state = crypto.randomUUID();
  setCookie(c, "oauth_state", state, { httpOnly: true, sameSite: "Lax", path: "/auth" });
  const url = new URL("https://github.com/login/oauth/authorize");
  url.searchParams.set("client_id", GITHUB_CLIENT_ID);
  url.searchParams.set("redirect_uri", REDIRECT_URI);
  url.searchParams.set("scope", "read:user user:email");
  url.searchParams.set("state", state);
  return c.redirect(url.toString());
});

// 2) Handle the callback: verify state, exchange code, fetch profile
app.get("/auth/callback", async (c) => {
  if (c.req.query("state") !== getCookie(c, "oauth_state")) {
    return c.json({ error: "state mismatch" }, 400);      // CSRF protection
  }
  const code = c.req.query("code")!;

  const tokenRes = await fetch("https://github.com/login/oauth/access_token", {
    method: "POST",
    headers: { Accept: "application/json", "Content-Type": "application/json" },
    body: JSON.stringify({
      client_id: GITHUB_CLIENT_ID, client_secret: GITHUB_CLIENT_SECRET,
      code, redirect_uri: REDIRECT_URI,
    }),
  });
  const { access_token } = await tokenRes.json();

  const profile = await (await fetch("https://api.github.com/user", {
    headers: { Authorization: `Bearer ${access_token}`, "User-Agent": "bun-app" },
  })).json();

  const user = await upsertUserFromProvider("github", profile);

  // 3) Issue YOUR OWN session (same refresh-cookie + access-token flow)
  setRefreshCookie(c, await refreshToken(user.id));
  return c.redirect(`/#token=${await accessToken(user.id)}`);
});
OIDC (e.g. Google, Auth0) is the same shape, plus an id_token (a JWT) you verify against the provider's JWKS. Always validate state to block CSRF on the callback, and keep client secrets in .env.local.

Bun.s3 — object storage

Bun.s3 (equivalent to new Bun.S3Client() reading S3_*/AWS_* env vars) gives Blob-shaped access to any S3-compatible service (AWS, R2, Spaces, MinIO, Supabase).

import { s3, S3Client } from "bun";

// Explicit client (multiple buckets / non-AWS endpoints)
const client = new S3Client({
  accessKeyId: Bun.env.S3_ACCESS_KEY_ID!,
  secretAccessKey: Bun.env.S3_SECRET_ACCESS_KEY!,
  bucket: "my-bucket",
  // endpoint: "https://<account>.r2.cloudflarestorage.com",  // Cloudflare R2
});

// Read / write like a file
const file = client.file("reports/q3.json");
const data = await file.json();
await file.write(JSON.stringify({ ok: true }), { type: "application/json" });
await file.delete();

Presigned upload — let users upload straight to S3

// Server issues a short-lived PUT URL (synchronous, no network call)
app.post("/upload-url", (c) => {
  const key = `uploads/${crypto.randomUUID()}`;
  const url = s3.presign(key, {
    method: "PUT",
    expiresIn: 3600,          // 1 hour
    type: "image/png",
  });
  return c.json({ url, key });
});

The client then PUTs the file to that URL directly — your server never proxies the bytes.

Redirect a download to a presigned URL

app.get("/download/:key", (c) => {
  // Passing an S3File as a Response body emits a 302 to a presigned URL
  return new Response(s3.file(c.req.param("key")));
});
Large files: s3.file(key).writer({ partSize, queueSize, retry }) streams multipart uploads automatically. The s3:// protocol also works through plain fetch() and Bun.file() — see File I/O.
